## What it is
The `site/` folder is the built wiki, ready to be shown: `index.html`, `assets/` (the compiled Elm app `app.js`, `boot.js` and `style.css`) and `data/` (the graph and page files in [JSON](https://en.wikipedia.org/wiki/JSON), JavaScript Object Notation, a plain-text data format).

## What it does
It is everything the browser needs after login. Its `index.html` tells the browser not to offer its own translation of the page. Nothing in it is ever sent before login.

## How it does it
It is generated by [[wiki-build]] and not committed to git (it is derived, so it can always be regenerated). It is served from disk by the [[wiki-router]]. Which folder is served is set by `WIKI_SITE_DIR`. Since 2026-10-26 the service reads a release folder, `~/.local/share/wiki/releases/<commit>`, chosen by a systemd drop-in (a small file that overrides one setting of [[wiki-service]]), so a publish shows on the site only after a release folder is built from the published commit and the drop-in points at it; removing the drop-in returns to `~/dev/wiki/site`.

## Where it sits in the pipeline
Between [[wiki-build]] and the [[wiki-router]].

## Who receives its output
The [[wiki-router]].
